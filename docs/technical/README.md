## 技术栈

### 前端技术
- **框架**：Next.js 16 + React 19
- **UI库**：shadcn/ui + Tailwind CSS
- **状态管理**：Zustand
- **表格组件**：@tanstack/react-table
- **图标库**：lucide-react

### 后端技术
- **API**：Next.js API Routes
- **数据库**：IndexedDB（当前）、计划支持PostgreSQL
- **ORM**：Prisma（计划）
- **认证**：NextAuth.js（计划）

### 开发工具
- **包管理**：npm/yarn/pnpm
- **构建工具**：Next.js内置
- **代码规范**：ESLint + TypeScript
- **测试框架**：Vitest（计划）

## 架构设计原则

1. **模块化**：按功能模块划分组件和业务逻辑
2. **类型安全**：使用TypeScript进行严格类型检查
3. **状态分离**：UI状态与业务数据分离
4. **可扩展**：设计支持未来功能扩展的架构

## 技术规范

### 代码组织
```
src/
├── app/           # Next.js App Router页面
├── components/    # UI组件
│   ├── ui/        # shadcn/ui组件
│   ├── layout/    # 布局组件
│   └── voucher/   # 凭证相关组件
├── stores/        # Zustand状态管理
├── lib/           # 业务逻辑和工具函数
│   ├── data/      # 静态数据
│   ├── accounting.ts
│   ├── ai-learning.ts
│   └── template-engine.ts
└── types/         # TypeScript类型定义
```

### 组件命名
- 使用 PascalCase：`VoucherEntryGrid`
- 文件使用 kebab-case：`voucher-entry-grid.tsx`
- 常量使用 UPPER_SNAKE_CASE：`VOUCHER_STATUS_DRAFT`

### API设计规范
- RESTful API设计
- 统一的响应格式
- 适当的HTTP状态码
- 完善的错误处理

## 开发流程

1. **需求确认** → 技术方案设计
2. **架构评审** → 通过后进入开发
3. **编码实现** → 遵循代码规范
4. **代码审查** → 至少一人审查
5. **测试验证** → 单元测试 + 集成测试
6. **部署上线** → 生产环境发布
