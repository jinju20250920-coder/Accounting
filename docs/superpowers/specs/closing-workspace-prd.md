# 金桔财务系统智能做账工作台 PRD

> 2026-05-11 修订：产品名称从 Closing Workspace / 月结工作台调整为“智能做账工作台”。这里的“智能”不等同于 AI 自动做账，而是指系统基于会计规则、科目余额、业务数据和当前账期，主动生成做账任务、风险提醒和下一步建议，帮助不熟悉做账流程的财务人员完成本月做账。

## 1. 背景与现状分析

### 1.1 当前系统能力

通过对 `http://localhost:3000/` 页面响应、路由结构和源码模块的分析，当前金桔财务系统已经具备较完整的财务核算功能，主要包括：

- 财务仪表盘：首页展示库存现金、应收应付净头寸、本月收入、凭证数量、收支趋势、账龄分析和智能通知。
- 凭证管理：支持新增凭证、查看凭证、草稿、审核中、已记账、已冲销等状态。
- 科目余额：基于已记账凭证生成科目余额明细。
- 报表查询：资产负债表、损益表、现金流量表。
- 往来管理：往来单位、应收账龄、应付账龄、核销记录。
- 资金管理：银行流水导入、银行账户、资金结算中心、银行规则。
- 发票管理：进项发票、销项发票、发票资金一览、发票生成凭证、发票核销。
- 资产管理：固定资产、固定资产汇总、折旧、处置、拆分、合并、待摊费用、无形资产摊销。
- 账套与期间：多账套、当前期间、期间关闭与重开。
- 权限体系：用户、角色、权限、账套级角色。
- 本地数据能力：SQLite/本地持久化，适合桌面端或单机财务场景。

### 1.2 当前产品形态问题

当前系统属于“功能集合型财务软件”：功能较多，但用户仍需要自己判断下一步。

主要问题：

- 首页是财务指标仪表盘，不是月结工作台。
- 菜单按功能组织，用户需要知道自己该进哪个模块。
- 期间管理已有关闭能力，但缺少“关闭前检查清单”。
- 银行、发票、固定资产、往来、报表之间缺少统一任务状态。
- 系统知道很多数据，但没有把数据转化为“本月待办”和“月结阻塞项”。
- 智能通知目前偏凭证状态，未覆盖完整月度做账流程。
- AI 价值还没有落到明确的财务工作流动作上。

### 1.3 产品升级判断

系统下一阶段不应继续单纯增加菜单功能，而应增加一层：

> 月结做账财务工作流引导平台 Closing Workspace

它不是替代原有凭证、发票、银行、资产、报表模块，而是在现有模块之上增加“状态层、任务层、检查层、引导层”。

## 2. 产品定位

### 2.1 定位

Closing Workspace 是金桔财务系统中的“月度做账与月结工作台”。

它将系统从：

> 功能驱动型财务软件

升级为：

> 任务驱动型财务工作流平台

### 2.2 核心目标

让用户打开系统后，不再先看菜单，而是直接知道：

- 本月做账进度是多少。
- 哪些数据还没导入。
- 哪些业务还没生成凭证。
- 哪些往来没有核销。
- 哪些财务检查存在风险。
- 当前是否可以生成报表。
- 当前是否可以月结锁账。
- 下一步应该处理什么。

### 2.3 产品原则

- 任务先于菜单：系统主动给出任务，而不是让用户找功能。
- 状态先于数据：系统核心不是有哪些数据，而是本月财务状态是否闭环。
- 检查先于月结：月结不是一个按钮，而是一套前置检查与工作流。
- 规则先于 AI：MVP 先用确定性规则做检查，AI 作为解释、建议和异常识别增强。
- 复用现有模块：不重做银行、发票、凭证、资产、报表，只新增引导与状态引擎。

## 3. 用户角色

### 3.1 会计

职责：

- 导入银行流水、发票、资产数据。
- 生成凭证。
- 处理待核销往来。
- 修复异常数据。
- 发起月结检查。

关注点：

- 今天该做什么。
- 哪些任务未完成。
- 哪些数据有问题。
- 点哪里可以处理。

### 3.2 财务主管

职责：

- 审核关键凭证与异常。
- 查看月结进度。
- 确认月结检查结果。
- 执行锁账或反月结。

关注点：

- 月结是否可关闭。
- 风险是否可接受。
- 谁负责处理阻塞项。
- 关闭期间是否有审计记录。

### 3.3 管理员

职责：

- 配置任务模板。
- 配置行业模板。
- 配置检查规则。
- 配置角色权限。

关注点：

- 不同企业流程是否可定制。
- 哪些任务必须完成。
- 哪些异常阻塞月结。

## 4. MVP 范围

### 4.1 第一版必须实现

1. Closing Workspace 首页

- 本月完成进度。
- 待办任务。
- 异常与风险。
- 智能建议。
- 月结准备状态。

2. 月度任务中心

- 自动生成本月任务。
- 任务状态：未开始、进行中、已完成、异常、已跳过。
- 任务依赖。
- 任务负责人。
- 任务跳转到对应业务模块。

3. 基础检查规则

- 银行流水是否导入。
- 银行流水是否存在未生成凭证记录。
- 发票是否导入。
- 发票是否存在未生成凭证记录。
- 固定资产是否存在本月待折旧。
- 是否存在未审核或未记账凭证。
- 凭证借贷是否平衡。
- 是否存在应收应付未核销余额。
- 三大报表是否已生成或可生成。

4. 月结前检查

- 一键执行月结检查。
- 区分阻塞项和提醒项。
- 阻塞项必须处理后才允许锁账。
- 提醒项允许主管确认后继续月结。

5. 期间锁账入口

- 复用现有期间关闭能力。
- 增加锁账前检查。
- 增加关闭日志。
- 增加反月结权限控制。

### 4.2 第一版暂不实现

- AI 自动做账全流程。
- 多行业复杂模板。
- 审批流引擎。
- 复杂异常预测。
- 自动跨模块批处理。
- 外部消息通知。

这些放在后续版本。

## 6. 工作台首页设计

### 6.1 页面目标

首页要回答一个问题：

> 这个账套本月能不能完成做账并月结？

### 6.2 页面模块

1. 顶部期间栏

- 当前账套。
- 当前期间。
- 期间状态：未开始、做账中、待检查、可月结、已锁账。
- 切换期间。

2. 本月完成进度

- 总完成率。
- 已完成任务数。
- 待处理任务数。
- 异常数量。
- 阻塞项数量。

3. 下一步推荐

按任务依赖和异常优先级生成：

- 请先导入银行流水。
- 有 15 张进项发票未生成凭证。
- 固定资产尚未计提折旧。
- 存在 3 笔客户回款未核销。
- 建议生成本月资产负债表。

4. 本月待办

每条待办展示：

- 任务名称。
- 所属阶段。
- 状态。
- 异常数量。
- 负责人。
- 操作按钮。

5. 风险提醒

风险分级：

- 阻塞：不处理不能月结。
- 高风险：建议处理，可由主管确认继续。
- 提醒：不阻塞流程。

6. 月结准备卡片

展示：

- 检查进度。
- 阻塞项。
- 可月结状态。
- 一键执行月结检查。
- 进入月结锁账。

## 7. 月度工作流

### 7.1 阶段一：数据采集

任务：

- 银行流水导入。
- 进项发票导入。
- 销项发票导入。
- 固定资产新增检查。

检查规则：

- 是否存在配置了银行账户但本月无流水导入。
- 是否存在重复银行流水。
- 是否存在银行流水未生成凭证。
- 是否存在重复发票。
- 是否存在发票跨期。
- 是否存在发票未生成凭证。
- 是否存在固定资产发票但未建资产卡片。

### 7.2 阶段二：自动做账

任务：

- 银行流水生成凭证。
- 进项发票生成凭证。
- 销项发票生成凭证。
- 固定资产取得凭证。
- 固定资产折旧凭证。
- 待摊费用摊销凭证。

检查规则：

- 自动规则是否匹配失败。
- 是否存在待确认科目。
- 是否存在生成失败。
- 是否存在同一业务单据重复入账。

### 7.3 阶段三：对账核销

任务：

- 银行对账。
- 应收核销。
- 应付核销。
- 发票收付款状态检查。

检查规则：

- 是否存在收款流水未匹配销售发票。
- 是否存在付款流水未匹配采购发票。
- 是否存在发票已收付款但未核销。
- 是否存在长期未核销往来。

### 7.4 阶段四：财务检查

任务：

- 凭证平衡检查。
- 凭证断号检查。
- 未审核凭证检查。
- 跨期凭证检查。
- 辅助核算检查。
- 科目余额异常检查。

检查规则：

- 借贷不平凭证必须阻塞月结。
- 草稿或审核中凭证默认阻塞月结。
- 当前期间以外日期凭证提示跨期风险。
- 往来科目缺少客户或供应商辅助信息时提示风险。

### 7.5 阶段五：结转与报表

任务：

- 损益结转。
- 成本结转。
- 生成资产负债表。
- 生成利润表。
- 生成现金流量表。
- 生成科目余额表。
- 生成固定资产清单。
- 生成往来账龄表。

检查规则：

- 收入、费用类科目未结转时，提示需要结转。
- 报表不平时阻塞月结。
- 资产负债表不平衡时阻塞月结。
- 报表生成时间早于最后一张凭证更新时间时提示需要重生成。

### 7.6 阶段六：月结锁账

任务：

- 执行月结检查。
- 财务主管确认。
- 锁定期间。
- 生成月结日志。
- 创建下一期间。

锁账后限制：

- 禁止新增本期凭证。
- 禁止修改本期凭证。
- 禁止删除本期凭证。
- 禁止修改本期发票凭证关联。
- 禁止修改本期资产折旧记录。

反月结：

- 仅财务主管或管理员可操作。
- 必须填写原因。
- 必须记录日志。
- 反月结后本期状态回到“做账中”。

## 8. 任务状态引擎

### 8.1 核心概念

Closing Task Engine 负责把现有业务数据转成月度任务状态。

它不直接替代业务模块，只负责：

- 生成任务。
- 计算状态。
- 执行检查。
- 统计进度。
- 给出下一步建议。

### 8.2 任务状态

```text
not_started  未开始
in_progress  进行中
completed    已完成
warning      提醒
exception    异常
blocked      阻塞
skipped      已跳过
```

### 8.3 任务阶段

```text
data_collection    数据采集
auto_accounting    自动做账
reconciliation     对账核销
financial_check    财务检查
reporting          结转报表
period_close       月结锁账
```

## 10. 检查规则清单

### 10.1 银行流水

- 本期无银行流水导入。
- 配置了银行账户但无流水。
- 流水重复。
- 流水未生成凭证。
- 流水规则匹配失败。
- 大额流水未标记业务类型。

### 10.2 发票

- 发票重复。
- 发票跨期。
- 发票未生成凭证。
- 发票已生成凭证但凭证被删除或冲销。
- 进项发票未付款。
- 销项发票未收款。
- 税额与金额关系异常。

### 10.3 固定资产

- 本月新增资产未建卡。
- 已建卡但未生成取得凭证。
- 本月应折旧但未计提。
- 折旧记录未生成凭证。
- 处置资产未生成处置凭证。

### 10.4 凭证

- 借贷不平。
- 凭证断号。
- 草稿凭证未处理。
- 审核中凭证未记账。
- 当前期间存在跨期凭证。
- 单据号重复入账。
- 往来科目缺少客户或供应商。

### 10.5 往来核销

- 应收余额未核销。
- 应付余额未核销。
- 发票收付款状态与核销记录不一致。
- 客户回款未匹配销售发票。
- 供应商付款未匹配采购发票。

### 10.6 报表

- 资产负债表不平。
- 报表数据早于最后凭证更新时间。
- 损益类科目未结转。
- 现金流量项目缺失。

## 11. 智能建议规则

系统按照以下优先级生成下一步建议：

1. 先处理阻塞项。
2. 再处理依赖链前置任务。
3. 再处理高风险异常。
4. 再推荐报表和月结动作。

示例：

- 如果银行流水未导入，则推荐“请先导入银行流水”。
- 如果发票已导入但未生成凭证，则推荐“建议批量生成发票凭证”。
- 如果固定资产本月未折旧，则推荐“请计提本月固定资产折旧”。
- 如果凭证存在草稿，则推荐“请审核或删除草稿凭证”。
- 如果所有检查通过，则推荐“本月已满足月结条件，建议执行锁账”。

## 14. 关键交互流程

### 14.1 进入本月工作台

1. 用户进入首页。
2. 系统读取当前账套与当前期间。
3. 如果本期任务实例不存在，自动按模板生成。
4. 系统执行轻量检查。
5. 首页展示本月进度、待办、风险和下一步建议。

### 14.2 处理任务

1. 用户点击任务“去处理”。
2. 系统跳转到对应业务模块。
3. 用户完成导入、生成凭证、核销或修复。
4. 回到工作台后系统重新检查。
5. 任务状态自动更新。

### 14.3 月结检查

1. 用户点击“执行月结检查”。
2. 系统运行全部检查规则。
3. 展示检查结果。
4. 如果存在阻塞项，不允许锁账。
5. 如果只有提醒项，财务主管可确认继续。
6. 检查通过后进入锁账。

### 14.4 月结锁账

1. 用户点击“锁定本期”。
2. 系统确认权限。
3. 系统再次执行关键检查。
4. 写入月结日志。
5. 将期间状态改为 locked/closed。
6. 自动创建或切换到下一期间。

## 17. 结论

Closing Workspace 的核心价值不是新增一个“月结页面”，而是在现有财务系统上建立一层“月度状态操作系统”。

当前金桔财务系统已经具备足够多的业务模块，下一步最值得做的是：

> 把功能组织成任务，把数据转化成状态，把异常转化成行动，把月结变成可控流程。

第一版只要实现“用户能依赖工作台完成本月做账检查并安全锁账”，产品方向就成立。

### 18.2 首页设计修订

首页优先回答：

- 本月账做完了吗？
- 下一步该做什么？
- 哪些事项阻塞月结？

- 异常与风险。
- 月结准备。
- 经营概览。

### 18.3 规则口径修订

- 银行流水导入是每月必查项。
- 发票不是每月必导入项；本期没有发票时不提醒“请导入发票”。
- 如果本期已有发票，则检查是否生成凭证、是否核销、是否跨期。
- 固定资产提醒口径改为“固定资产相关科目存在余额，本月未发现折旧计提”。
- 固定资产相关科目至少包括固定资产原值、累计折旧、固定资产清理、在建工程。
- 提醒需要展示固定资产原值余额、累计折旧余额和本期折旧发生额，避免只说“固定资产科目有余额”。
- 待摊费用或长期待摊费用相关科目存在余额，且本期未发现摊销时提醒。
- 重点科目有余额但本期无变化时，提示用户确认是否正常。
- 这些余额驱动提醒默认是提醒项，不直接作为阻塞项；明确违反规则的事项才作为阻塞项。

### 18.4 首页任务展示与用户编辑

智能做账工作台首页必须展示一组清晰、可编辑的本月做账任务。任务状态采用“系统预设，用户编辑”的模式：

1. 系统根据当前账套、当前期间、科目余额和业务数据自动生成预设任务状态。
2. 用户可以在首页对每个任务进行本月确认或状态修改。
3. 用户修改后的状态按“账套 + 期间 + 任务编码”保存。
4. 用户修改不改变原始会计数据，只影响本期工作台任务状态和提醒展示。
5. 如果系统后续重新检查发现明确阻塞项，仍应重新提示用户处理。
