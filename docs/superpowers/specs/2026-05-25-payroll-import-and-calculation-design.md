# 工资导入与薪酬计算模块设计

## 1. 目标与范围

### 1.1 背景

当前系统已经具备工资相关的外围能力：

- 银行规则可以识别工资、社保、公积金付款并映射至应付职工薪酬。
- 凭证模板包含工资计提模板。
- 月结检查包含工资个税、社保公积金检查项。

但系统尚无工资业务主数据、工资计算入口或工资表导入页面，月结检查也无法读取工资办理状态。

### 1.2 第一版目标

新增 `薪酬管理` 页面，形成以下闭环：

1. 按账套和工资所属期间导入工资表。
2. 配置社保、公积金及个税计算参数。
3. 计算应发工资、个人承担、企业承担、应纳税所得额、个税和实发工资。
4. 审核和保存工资批次及明细。
5. 汇总并导出本期工资计算结果。
6. 为月结检查提供工资处理状态和入口。

### 1.3 第一版不包含

- 不维护全国各城市社保政策库。
- 不自动推断适用地区或险种上下限。
- 不处理全年一次性奖金单独计税、离职补偿等特殊计税场景。
- 不在第一版自动生成或自动过账凭证。
- 不自动与银行回单、社保账单或个税申报系统核销。

以上功能可在工资数据和计算结果稳定后继续扩展。

## 2. 方案选择

### 2.1 可选方案

| 方案 | 内容 | 优点 | 约束 |
| --- | --- | --- | --- |
| A. 仅做导入展示 | 导入工资表并保存，不重新计算 | 开发最小 | 无法支持个税和社保核算，也无法支撑月结检查 |
| B. 导入加可配置计算引擎 | 导入、计算、汇总、保存、月结联动 | 业务闭环完整，规则可审计且适应地区差异 | 需要新增数据表和测试 |
| C. 完整薪酬结算平台 | 增加政策库、申报、支付、凭证自动化 | 覆盖范围最大 | 超出当前账务产品的合理迭代范围 |

### 2.2 选定方案

采用方案 B。社保和公积金比例由用户维护；个税采用可追溯的参数化累计预扣预缴模型。这样既提供可靠的薪酬计算基础，也避免把特定地区政策误设为系统统一规则。

## 3. 用户流程与页面结构

### 3.1 导航

- 侧边栏新增一级入口：`薪酬管理`。
- 页面路由：`/payroll`。
- 月结检查中的 `工资是否计提、发放并完成个税处理` 和 `社保、公积金是否计提并与账单核对` 跳转至 `/payroll`。

### 3.2 页面布局

页面采用工作台式密集布局，优先展示当期办理动作和计算结果：

1. 顶部工具栏
   - 账套与工资月份显示。
   - `导入工资表`、`下载模板`、`导出结果`、`计算设置` 操作。
   - 批次状态：草稿、已计算、已确认。
2. 本月汇总区
   - 员工人数、应发合计、公司成本合计、个税合计、实发合计。
3. 明细表格
   - 展示导入字段、计算字段和校验状态。
   - 支持行级编辑后重新计算。
4. 设置抽屉或对话框
   - 社保、公积金配置。
   - 个税计算模式和参数版本。
   - 基数上下限及默认适用方式。
5. 校验和处理提示
   - 明确提示缺失字段、无效数值、未设置比例、未确认批次等阻断问题。

### 3.3 工资批次状态

| 状态 | 含义 | 页面允许操作 |
| --- | --- | --- |
| `draft` | 已导入或编辑，结果尚未确认 | 编辑、调整设置、重新计算、删除 |
| `calculated` | 已完成计算但尚未确认 | 查看、重新计算、确认、导出 |
| `confirmed` | 本期工资结果已确认 | 查看、导出；修改时需退回草稿 |

月结检查仅把 `confirmed` 批次视为工资计算完成的依据；实际计提、缴纳和申报完成仍由检查规则与后续凭证/核对能力判断。

## 4. 导入数据

### 4.1 支持格式

- `.xlsx`
- `.xls`
- `.csv`

沿用项目现有 `xlsx` 解析方式，先解析为预览数据，用户确认后再保存批次。

### 4.2 导入模板字段

| 字段 | 必填 | 用途 |
| --- | --- | --- |
| 工号 | 是 | 同期员工明细的稳定识别字段 |
| 姓名 | 是 | 显示和核对 |
| 部门 | 否 | 费用分析及后续凭证分摊 |
| 基本工资 | 是 | 应发组成 |
| 奖金 | 否 | 应发组成 |
| 津贴补贴 | 否 | 应发组成 |
| 其他应发 | 否 | 应发组成 |
| 请假扣款 | 否 | 应发扣减 |
| 其他税前扣减 | 否 | 应发扣减 |
| 社保缴费基数 | 否 | 为空时按配置规则取值 |
| 公积金缴费基数 | 否 | 为空时按配置规则取值 |
| 专项附加扣除 | 否 | 个税扣除 |
| 其他依法扣除 | 否 | 个税扣除 |
| 前期累计收入 | 否 | 年中接入时用于衔接累计预扣 |
| 前期累计个人社保公积金 | 否 | 年中接入时用于衔接累计扣除 |
| 前期累计专项附加扣除 | 否 | 年中接入时用于衔接累计扣除 |
| 前期累计其他依法扣除 | 否 | 年中接入时用于衔接累计扣除 |
| 前期累计已预扣税额 | 否 | 年中接入时用于计算本期应补扣税额 |

### 4.3 导入校验

- 工号、姓名、基本工资缺失时，该行不能保存。
- 金额字段必须为非负数；扣减项以正数输入，由系统进行减项处理。
- 同一账套、同一工资月份、同一批次内工号不得重复。
- 缴费基数缺失时，只有设置了默认取值规则才可计算。
- 导入失败行保留在预览区，并显示行号和原因，不写入数据库。

## 5. 计算规则

### 5.1 计算边界

工资计算是纯计算服务，不直接写凭证、不直接改变月结状态。输入为工资明细和当期配置，输出为可保存、可追溯的计算结果。

### 5.2 应发与实发

```text
应发工资 = 基本工资 + 奖金 + 津贴补贴 + 其他应发 - 请假扣款 - 其他税前扣减

实发工资 = 应发工资 - 个人社保合计 - 个人公积金 - 个税 - 其他税后扣减
```

### 5.3 社保与公积金

配置按账套保存并带有效月份，字段包括：

- 养老、医疗、失业、工伤、生育、大病补充等险种是否启用。
- 每个险种的个人比例和企业比例。
- 公积金个人比例和企业比例。
- 社保基数、公积金基数的下限和上限。
- 导入未提供基数时采用 `应发工资` 或配置默认基数。

```text
适用缴费基数 = min(max(输入或默认基数, 下限), 上限)
个人缴费 = 适用缴费基数 * 个人比例
企业缴费 = 适用缴费基数 * 企业比例
```

比例和基数是地区及单位配置，不提供跨地区自动默认值。新账套必须完成设置后才能确认工资批次。

### 5.4 个税

第一版按工资薪金的累计预扣预缴模型计算，税率参数保存为可追溯配置快照：

```text
累计应纳税所得额 =
  累计收入
  - 累计基本减除费用
  - 累计个人社保公积金
  - 累计专项附加扣除
  - 累计其他依法扣除

本期应预扣个税 =
  累计应纳税所得额 * 适用预扣率
  - 速算扣除数
  - 累计已预扣税额
```

- 基本减除费用、税率级距、预扣率、速算扣除数不散落在页面代码内，统一属于个税配置版本。
- 实现时初始化默认个税配置前，必须核对适用于交付时点的官方公开规则，并在设置区域显示配置版本和生效日期。
- 若用户从年中开始使用系统，必须能导入累计前期收入、扣除和已预扣税额，否则不得把结果标识为完整累计计算。

### 5.5 舍入

- 单项计算金额统一保留两位小数，按人民币分四舍五入。
- 汇总金额使用已舍入的明细金额求和，确保导出结果与明细一致。

## 6. 数据模型与 SQLite 持久化

### 6.1 存储原则

- 工资批次、工资明细、计算配置与计算结果属于业务主数据，持久化至 SQLite。
- 所有表均包含 `accountSetId`，并按月份隔离查询。
- 页面临时筛选、未提交的交互状态可保存在 React state，不作为业务数据。

### 6.2 表设计

```sql
CREATE TABLE IF NOT EXISTS payroll_batches (
  id TEXT PRIMARY KEY,
  accountSetId TEXT NOT NULL,
  payrollPeriod TEXT NOT NULL,
  batchName TEXT NOT NULL,
  status TEXT NOT NULL,
  sourceFileName TEXT,
  employeeCount INTEGER NOT NULL DEFAULT 0,
  grossTotal REAL NOT NULL DEFAULT 0,
  employerCostTotal REAL NOT NULL DEFAULT 0,
  taxTotal REAL NOT NULL DEFAULT 0,
  netTotal REAL NOT NULL DEFAULT 0,
  calculationConfigSnapshot TEXT NOT NULL,
  createdAt TEXT NOT NULL,
  updatedAt TEXT NOT NULL,
  confirmedAt TEXT
);

CREATE TABLE IF NOT EXISTS payroll_items (
  id TEXT PRIMARY KEY,
  batchId TEXT NOT NULL,
  accountSetId TEXT NOT NULL,
  payrollPeriod TEXT NOT NULL,
  employeeCode TEXT NOT NULL,
  employeeName TEXT NOT NULL,
  departmentName TEXT,
  inputData TEXT NOT NULL,
  calculationResult TEXT NOT NULL,
  validationStatus TEXT NOT NULL,
  validationMessages TEXT NOT NULL,
  createdAt TEXT NOT NULL,
  updatedAt TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS payroll_calculation_configs (
  id TEXT PRIMARY KEY,
  accountSetId TEXT NOT NULL,
  effectivePeriod TEXT NOT NULL,
  socialInsuranceConfig TEXT NOT NULL,
  housingFundConfig TEXT NOT NULL,
  individualTaxConfig TEXT NOT NULL,
  policyLabel TEXT NOT NULL,
  policyEffectiveDate TEXT NOT NULL,
  createdAt TEXT NOT NULL,
  updatedAt TEXT NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_payroll_batches_period
  ON payroll_batches(accountSetId, payrollPeriod);
CREATE INDEX IF NOT EXISTS idx_payroll_items_batch
  ON payroll_items(accountSetId, batchId);
CREATE INDEX IF NOT EXISTS idx_payroll_config_period
  ON payroll_calculation_configs(accountSetId, effectivePeriod);
```

JSON 字段用于保存可演进的导入列、险种组成和计算快照，避免第一版将地区差异扩展成大量不稳定列。

### 6.3 服务与状态边界

- `src/lib/payroll.ts`：纯函数、类型和计算校验，无数据库依赖。
- `src/lib/payroll-import.ts`：Excel/CSV 字段解析和预览校验。
- `src/lib/database/sqlite-service.ts`：建表迁移与工资批次、明细、配置 CRUD。
- `src/stores/usePayrollStore.ts`：页面的数据加载、保存和操作状态编排，业务数据最终以 SQLite 为准。

## 7. 月结检查与凭证边界

### 7.1 月结检查联动

工资模块提供月结可读取的状态：

- 当前期间是否存在已确认工资批次。
- 已确认批次是否完成个税计算。
- 已确认批次是否包含社保、公积金计算结果。

工资相关月结规则的详情入口改为 `/payroll`。第一版不因为保存工资表就自动标记“已计提、已发放、已申报或已缴纳”，避免把计算完成与账务执行混为一谈。

### 7.2 后续凭证扩展点

第一版保留以下后续动作的扩展位置，但不自动落账：

- 计提工资及企业承担社保公积金。
- 发放实发工资。
- 代扣代缴个人社保、公积金和个税。
- 缴纳单位及个人承担金额。

后续实现凭证功能时，应从已确认工资批次生成凭证预览，并与已有工资模板、银行流水规则对接。

## 8. 错误处理与审计

- 文件解析错误在预览阶段展示，不产生批次数据。
- 配置不足、累计数据不完整或明细验证失败时，禁止确认批次。
- 已确认批次修改前必须退回草稿状态，并保留更新时间。
- 工资明细为敏感业务数据，列表默认不展示证件号等非必要信息，第一版不导入身份证号。
- 保存配置、确认批次、退回草稿和删除草稿应纳入已有审计日志扩展范围。

## 9. 测试与验收

### 9.1 自动测试

- 纯函数测试：应发、社保、公积金、累计个税、实发、舍入和基数上下限。
- 导入测试：列映射、必填校验、重复工号、错误金额、CSV/Excel 格式。
- SQLite 服务测试：配置、批次和明细按账套/期间保存与读取。
- 月结联动测试：工资规则链接和已确认批次状态映射。

### 9.2 页面验收

- 能下载模板并导入一份有效工资表。
- 导入错误可定位至具体行并修正后重新计算。
- 设置不同社保、公积金比例后，明细和汇总同步变化。
- 确认后的批次在刷新页面后仍可读取。
- 月结检查可跳转到工资页面，并基于工资数据反映检查依据。

## 10. 实施顺序

1. 建立计算类型、纯函数及其测试。
2. 建立导入解析及验证测试。
3. 增加 SQLite 工资表和 CRUD 服务。
4. 建立 `usePayrollStore`。
5. 实现 `/payroll` 工作台、导入预览和设置界面。
6. 加入侧边栏入口与月结检查路由/状态联动。
7. 执行编译、测试和页面验证。

## 11. 已确定约束

- 主数据必须写入 SQLite，不将工资明细仅保存于 `localStorage`。
- 社保和公积金不预设为任何城市固定比例。
- 个税计算采用累计预扣预缴，并使用可追溯的配置版本。
- 第一版以导入、计算、确认、导出和月结联动为完成标准，不包含自动制证与外部申报。
