# 工资明细行内录入设计

## 1. 目标

在现有薪酬管理页面中补充接近 Excel 的手工维护能力，覆盖少量补录和导入后纠错场景，同时继续复用已有的工资批次、计算规则、SQLite 持久化和月结联动逻辑。

本次范围包括：

- 在工资计算明细表中直接新增工资行。
- 在未确认批次中直接编辑和删除工资行。
- 保存明细后自动重算个人结果及批次汇总。
- 已确认批次保持只读，必须退回草稿后才能修改。

本次不包括：

- 多单元格复制、粘贴、填充柄或键盘导航等完整电子表格能力。
- 新增独立的调整单、审批流或变更历史表。
- 改变个税、社保、公积金计算公式及月结认定条件。

## 2. 选择方案

采用“同一批次内行内录入”方案。

- Excel 导入与手工新增明细统一保存为 `PayrollItem`，不形成两套数据逻辑。
- 页面上的明细表既是查看区，也是未确认状态下的录入与修正区。
- 保存任一行后以当前计算配置重新生成该批次明细结果和顶部汇总。

不采用弹窗逐条维护，因为多员工补录时操作成本高；不采用调整单模式，因为当前需求是纠错和补录，而不是形成独立核算流水。

## 3. 用户交互

### 3.1 新增

- 工资计算明细标题区新增 `新增行` 按钮。
- 没有批次时，点击 `新增行` 创建当期手工维护批次，并在表格中增加空白编辑行。
- 已有未确认批次时，点击 `新增行` 在当前批次底部增加空白编辑行。
- 新增行中输入业务字段后点击 `保存`，系统计算结果并将数据写入 SQLite。

### 3.2 编辑

- 未确认批次的已保存明细行提供 `编辑` 操作。
- 点击后该行的输入字段切换为可编辑单元格，计算结果列保持只读。
- 点击 `保存` 后重算并刷新；点击 `取消` 放弃本次未保存修改。

### 3.3 删除

- 未确认批次的明细行提供 `删除` 操作。
- 删除后重算并刷新员工人数与金额汇总。
- 删除最后一条明细时保留空批次，用户可继续录入或删除整个批次。

### 3.4 锁定

- `confirmed` 批次不显示新增、编辑、删除入口。
- 用户点击 `退回草稿` 后，批次恢复可修改状态。
- `draft` 与 `calculated` 都允许编辑；编辑保存后统一标记为 `calculated`，提示结果需重新确认。

## 4. 行内字段与布局

编辑模式下表格采用横向滚动，输入列与计算结果列分区展示。

可编辑输入字段：

| 分组 | 字段 |
| --- | --- |
| 员工信息 | 工号、姓名、部门 |
| 应发项 | 基本工资、奖金、津贴补贴、其他应发 |
| 税前减项 | 请假扣款、其他税前扣减 |
| 缴费基数 | 社保缴费基数、公积金缴费基数 |
| 税务扣除 | 专项附加扣除、其他依法扣除 |
| 累计接入 | 前期累计收入、前期累计个人社保公积金、前期累计专项附加扣除、前期累计其他依法扣除、前期累计已预扣税额 |
| 税后减项 | 其他税后扣减 |

只读计算字段：

- 应发工资
- 个人社保
- 个人公积金
- 个税
- 实发工资
- 企业成本

查看状态默认继续使用精简结果列。进入新增或编辑状态时，在该行显示完整输入列，避免日常查看界面长期过宽。

## 5. 校验与计算

保存行前校验：

- 工号与姓名必填。
- 基本工资及所有金额输入必须是非负数。
- 同一批次内工号不得重复；编辑当前行时排除自身。
- 工资计算设置必须已保存；没有配置时提示用户先完成计算设置。

保存行后的处理：

1. 将当前行转换为 `PayrollInput`。
2. 使用当期计算配置调用现有 `calculatePayrollItem`。
3. 与当前批次其他明细共同调用 `summarizePayrollResults`。
4. 整批持久化并更新批次状态为 `calculated`。
5. 清除原确认时间，月结检查只有再次确认后才读取为有效工资证据。

## 6. 状态层与持久化

数据库表结构无需变化，复用 `payroll_batches` 与 `payroll_items`。

`usePayrollStore` 增加以下动作：

- `addManualItem(period, input)`：在当前或新建的手工批次中新增明细并重算。
- `updateItem(itemId, input)`：更新未确认批次中的一条明细并重算。
- `deleteItem(itemId)`：删除未确认批次中的一条明细并重算。

共用内部逻辑负责：

- 检查批次是否允许修改。
- 校验重复工号。
- 生成或保留明细 ID。
- 重算批次汇总。
- 调用现有 `savePayrollBatch` 完成 SQLite 持久化。

不增加只存于界面状态的业务明细；未保存的编辑行仅作为临时表单状态存在于页面组件中。

## 7. 错误处理与审计边界

- 表格行校验错误直接展示于当前编辑行，不写入数据库。
- 已确认批次尝试修改时，由状态层阻止并返回“请先退回草稿后修改”。
- 手工维护或编辑后，批次变为 `calculated`，需要用户再次确认，避免修正后沿用旧的月结证据。
- 本次沿用现有批次更新时间与确认时间，不新增独立字段级变更日志。

## 8. 测试与验收

自动化验证：

- 空批次新增首行会创建手工批次并生成计算结果。
- 已有批次新增、编辑和删除明细会同步更新汇总。
- 重复工号和负数输入被阻止。
- 已确认批次禁止新增、编辑和删除；退回后允许修改。
- 保存修改后批次回到 `calculated`，月结联动仍仅认 `confirmed`。

浏览器验收：

- 打开 `/payroll`，完成计算设置后点击 `新增行`。
- 在行内输入员工数据并保存，查看自动计算结果和汇总变化。
- 编辑该行后保存，确认结果随输入变化。
- 新增第二行后删除，确认汇总回退。
- 确认批次后，新增与编辑入口消失；退回草稿后重新可编辑。
