# Currency & FX Tab Design
# 币种与汇率页设计说明

## 1. Background

当前系统已经有币种管理页面 `/settings/currencies`，也已经具备账套本位币、币种档案和汇率数据结构。但页面只覆盖币种维护，没有提供每日汇率维护入口；银行账户页也有账户绑定能力，但没有显式的币种字段。

本次需求的目标是把“币种维护”和“每日汇率维护”收敛到同一个页面的两个 Tab 中，并让银行账户绑定支持币种字段，形成外币基础数据闭环。

## 2. Goals

- 在现有币种页中新增第二个 Tab，用于维护每日汇率。
- 汇率仅维护“中间价”，不引入买入价/卖出价。
- 银行账户绑定增加币种字段，并默认跟随账套本位币。
- 保持现有币种页的核心交互不变，尽量复用现有 store 和数据库层。

## 3. Scope

### Included

- `/settings/currencies` 页面增加两个 Tab：
  - 币种
  - 汇率
- 汇率 Tab 支持按日期查看、维护每日汇率。
- 银行账户页增加币种字段。
- 保存逻辑写入现有 `currencies`、`fxRates`、`bank_account_bindings` 数据结构。

### Excluded

- 不新增独立汇率路由页面。
- 不实现买入价/卖出价。
- 不实现期末汇兑损益重估入口。
- 不改凭证记账逻辑的业务口径。

## 4. UI Requirements

### 4.1 币种 Tab

保留当前币种页已有功能：

- 币种列表
- 本位币设置
- 启用/禁用
- 维护币别损益科目
- 导入/导出/模板

该 Tab 不做大结构调整，只允许对布局进行必要收敛，避免影响现有操作。

### 4.2 汇率 Tab

新增“每日汇率”维护区，建议包含：

- 日期筛选
- 汇率列表
- 新增汇率
- 编辑汇率
- 删除汇率

表格字段建议：

- 日期
- 币种
- 本位币
- 中间价
- 来源
- 创建时间
- 操作

交互规则：

- 本位币字段只读，来源于账套配置。
- 同一账套下，`日期 + 币种` 唯一。
- 仅维护中间价，不做多汇率类型。
- 汇率录入时默认展示账套本位币。

### 4.3 银行账户页

银行账户绑定新增币种字段：

- 新增/编辑绑定时可选择币种。
- 默认值跟随账套本位币。
- 不改变现有银行科目绑定逻辑。

## 5. Data Model

### 5.1 账套

继续使用账套级本位币配置：

- `baseCurrency`
- `baseCurrencyName`

### 5.2 币种

继续使用现有 `currencies` 表/Store。

### 5.3 汇率

继续使用现有 `fxRates` 表/Store，字段以：

- `accountSetId`
- `rateDate`
- `currencyCode`
- `baseCurrency`
- `middleRate`

为主。

### 5.4 银行账户绑定

在现有 `bank_account_bindings` 结构上增加/使用币种字段：

- `currency`

## 6. Functional Rules

1. 币种页仍是币种档案的主入口。
2. 汇率页只是每日中间价维护入口，不承担重估计算。
3. 银行账户绑定的币种字段必须和币种档案联动。
4. 账套本位币允许配置，不强制为 `CNY`。
5. 所有默认值都应来自当前账套，不做 hardcode。

## 7. Acceptance Criteria

- `/settings/currencies` 页面能在两个 Tab 间切换。
- 币种 Tab 的现有功能保持可用。
- 汇率 Tab 能按日期新增/编辑/删除每日中间价。
- 银行账户页能选择币种，并在保存后回显。
- 默认值能正确跟随账套本位币。
- 项目编译通过，现有币种页不被破坏。

## 8. Risks

- 现有币种页文件较大，容易把 UI 改动和数据改动混在一起，需控制 patch 粒度。
- 银行账户页当前包含科目绑定和格式引导流程，新增币种字段时要避免影响现有向导状态。
- 汇率表如果直接复用现有币种页，需要避免和币种列表的状态互相污染。
